# Lumen TV 1.2.0

## What is new

- **A new interface**, the one of LumenOS: cards, a selection that glides, pages that slide, an opening
  picture, a screen saver, short sounds and a quiet loop in the menus (switchable in *Settings*). In all
  16 languages. All three apps (Android TV, Samsung, LG) and the page Lumen serves to browsers show it.
- **Films from a drive connected to the television.** *USB drive* lists the volumes the television
  mounted and the folders and films on them, and plays them itself – no computer needed. On Android TV
  the player is Media3: Dolby and DTS go to the receiver as they are where the television allows it, HDR
  and the film's frame rate are the system's.
- **Blu-ray discs, read by the app itself** from a disc drive on USB (and from `.iso` images in the app's
  folder). The app speaks to the drive over USB (SCSI), reads the disc's file system (UDF 1.02–2.60,
  with metadata partition) and plays the titles natively with Media3 – not cast. The length and seeking
  of a title come from the stream's own clock. Discs with **AACS** play and rip when their key is in
  the key database `KEYDB.cfg` (the file libaacs uses; put it in the app's folder, or let the app
  load the community database from the net on your request: *Load the key database*). The decryption
  was checked against libaacs on a test disc: the result is identical.
- **Make MKV files of the titles**, like the desktop app: every title (playlist, so a film that runs
  through several clips comes out as one file) is remuxed into a Matroska file without re-encoding:
  H.264, H.265, MPEG-2, VC-1; AC-3, E-AC-3, DTS (with the HD part), TrueHD (with its AC-3 core as a
  second track), LPCM; PGS subtitles. Files go to *Copied discs* and play from there. *Copy the titles*
  writes the plain transport streams.
- Still there: *From Lumen* – the stream Lumen casts, with the television's remote operating Lumen.
- The Android app's source code is in the repository again: a rule in `.gitignore` (`lumen/`) had
  excluded the app's package folder (`io/github/lumen/tv`), so the Kotlin files were never committed and
  the APK of 1.1.0 was built without them. The app is now a WebView with this page and a native player.

## Checked, and limits

Run in the Android TV emulator (Android 14, ARM64, Apple Silicon): the interface and its keys, the
volumes and folders of the emulated storage, playing from them with seek, pause and the media keys,
Back, and a cast from a stand-in Lumen (found on the network, played as HLS, state reported). A Blu-ray
image (UDF 2.50) read bit-exact against the Linux kernel's UDF driver; an AACS-encrypted test disc
decrypted identically to libaacs, played natively and ripped on the device: the MKV decodes to the
same video frames and audio as the original (FFmpeg `framemd5`), has 200 of 200 subtitle packets, seeks
and plays in the app.
**Not tried on a real television or a real drive**: USB access to a disc drive (the emulator cannot
pass USB through), the system's USB permission dialog, Dolby/DTS passthrough, HDR, the Samsung and LG
apps with the new page.

What this cannot do, and says so on the screen: **BD+** discs (a program on the disc alters the
stream), **Ultra HD** discs (AACS 2 and drives that need new firmware), **DVD** with CSS (DVDs without it
play and copy; no MKV for DVD yet), **Cinavia**, and any disc whose key is not in the key database.
MakeMKV itself cannot run on Android; this is a separate implementation of the same job. Playing a
film that runs through several clips plays clip by clip (the MKV is one file). Menus of the disc
(BD-J, HDMV) are not played; titles are chosen from the list.
