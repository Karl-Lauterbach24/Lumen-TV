# Lumen TV 1.13.0

## What is new

- **4K discs play through MakeMKV.** MakeMKV fetches the keys of 4K discs from its servers (its "hashed keys", HK); for every net
  access it loads libcurl, which the app's Linux tree did not have – so MakeMKV took the net as off, said nothing about it, and
  reported "the volume key is unknown". The tree now has libcurl (built small, OpenSSL only) and libssl. Tested with *Alita: Battle
  Angel* (4K, AACS 2): the key database is downloaded, the titles read, the film starts.
- **The download is shown**: "MakeMKV is downloading its key database …" with a running bar (MakeMKV gives no figures for it).
- **Dolby Vision is played as its HEVC base layer** (HDR10) on a television without a Dolby Vision decoder; the player left the
  picture out before (sound only).
- **Reading the titles: a disc the drive cannot read is ejected and loaded again once**, then the user is asked to check it.

## Fixed

- **Stopping MakeMKV no longer hangs the drive.** The programs under proot get SIGTERM first; the drive shim holds it until the
  command in flight has its status. Killed between the two, the drive's USB bridge waited for good.
- The background reading of a disc's track names stopped a film that had just been started (it cleared its state before stopping
  MakeMKV); it now stops first, and it does not run for discs with a Java menu (BD-J), which it cannot read.
